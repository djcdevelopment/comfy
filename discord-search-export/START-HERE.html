Start here

This tool reads messages already rendered in Discord's search-results panel, accumulates pages locally, deduplicates by message ID, and saves or copies one JSON collection. Discord pagination remains manual.

What it does

  • Reads the visible search-results pane
  • Collects one Discord results page at a time
  • Persists progress across reloads
  • Saves or copies deduplicated JSON

What it avoids

  • No account or user token
  • No Discord API calls
  • No remote service or telemetry
  • No background page or service worker

What it cannot promise

  • It cannot establish data ownership
  • It cannot anonymize raw exports
  • It cannot survive every Discord redesign
  • It cannot delete files already downloaded

Responsible use

Access to a message is not automatically permission to republish or analyze it. Keep collection narrow, purposeful, and consistent with the relevant project and privacy commitments.

Never give a helper your Discord token, cookies, credentials, invite links, or raw message export.

Selector debugging needs only a reviewed structural diagnostic. If a person or agent asks for authentication material, stop.

Before collecting

  • Confirm ownership or explicit authorization.
  • Prefer from:yourname and additional narrow filters.
  • Decide the minimum fields and date range actually required.
  • Know where the resulting JSON will be stored and who can see it.

After collecting

  • Use Reset to clear the browser accumulator.
  • Redact or anonymize before sharing downstream.
  • Delete exports and debug reports when no longer needed.
  • Do not redistribute this private package without permission.

The first Add page action in each page session shows an authorization reminder and detected search string. Confirmation is a deliberate speed bump, not an identity or ownership check.

Precise capability statement

“No declared permissions” does not mean “cannot read Discord.” The matched content script can inspect the rendered Discord page while it is loaded. It also uses Discord-origin localStorage, browser downloads, and the clipboard after user interaction.

Install in Chrome or Edge

  1. Extract the ZIP. Keep START-HERE.html and the extension folder together. Do not try to load the ZIP directly.
  2. Open the extensions page. Type chrome://extensions or edge://extensions into the browser address bar.
  3. Enable Developer mode. The switch is normally near the top-right of the extensions page.
  4. Choose Load unpacked. Select the extracted extension folder—the folder that directly contains manifest.json.
  5. Open or reload Discord. A small draggable panel appears at the bottom-left. It is present on Discord even before a search, but collection requires visible results.
Expected extension card

Name: Discord Search Exporter (local) · Version: 0.2.0. If the version or folder contents differ, stop and re-check the package.

Quick start

  1. Run a narrow Discord search. Prefer from:yourname. Add dates, channel, or other filters when they reduce unnecessary collection.
  2. Optionally click Debug. A privacy-minimized structural report confirms whether the results pane and message hooks are detected.
  3. Click Add page. Review the responsible-use reminder and detected query, then confirm only if you are authorized. The status shows new and total messages.
  4. Advance Discord manually. Click Discord's next-page control, wait for the new page, then click Add page again. Repeat through the final page.
  5. Export once. Use Save all for a formatted JSON download or Copy JSON when downloads are restricted. Re-adding a page is harmless because IDs are deduped.
  6. Reset and clean up. Reset clears the in-browser collection. Separately delete downloaded files or clipboard history when they are no longer needed.

Data, storage, and output

Progress survives Discord reloads so long multi-page exports do not have to restart. That convenience also means you must deliberately clear it.

Browser state

  • dse_accumulator_v1: messages keyed by message ID
  • dse_adds_v1: Add page press count
  • Location: Discord-origin localStorage
  • Cleanup: the panel's Reset control

Export fields

  • Message ID and timestamp
  • Author display name and message content
  • Channel name and Discord jump link when available
  • A channel label derived from the detected search query
{
  "channel": { "name": "search: from:yourname" },
  "messages": [
    {
      "id": "1234567890",
      "timestamp": "2026-01-01T12:00:00.000Z",
      "author": { "name": "yourname" },
      "content": "Example message",
      "channelName": "example-channel",
      "link": "discord.com/channels/..."
    }
  ]
}

Save output is pretty-printed; Copy JSON is compact. Both contain the same message records sorted by timestamp.

Troubleshooting

The panel does not appear
Confirm version 0.2.0 is enabled, reload the Discord tab, and inspect the extension card for errors. The manifest matches discord.com only; it will not appear on unrelated sites or other Discord domains.
“Could not find the search results pane”
Run a Discord search and leave its results panel visible. The extension intentionally refuses to fall back to the main chat scroller because doing so could collect messages outside the intended search.
Add page finds zero messages
Click Debug. Check foundScroller, contentNodeCount, hasTimeEls, and hasUsernameEls. If the scroller is missing or content count is zero while results are visible, the selectors near const SEL in content.js likely need retuning.
Status says “+0 new — same page?”
On a repeated page this is expected. On a fresh page, Discord's pager probably did not advance or did not finish rendering. Confirm the page changed, wait briefly, and try Add page once more.
Save is blocked or Copy JSON fails
Try the other export control. Copy uses the browser clipboard API with a legacy selection fallback. Save uses a local Blob download. Check browser download/clipboard policies and the panel status; do not add broad extension permissions as a first response.
An old collection appears after reload
The accumulator is intentionally persistent. Use Reset before starting a new search. Reset affects only browser state; delete any previously downloaded files separately.
Before sharing a debug report

Open it in a text editor. Version 2 removes message text, raw DOM IDs, raw control labels, and numeric Discord path segments, but review it anyway. Send only the smallest diagnostic necessary.

Local-agent prompt cookbook

These prompts keep a coding agent focused on the included source and preserve the local-only trust boundary. Attach only files named by the prompt, after reviewing them.

1. Audit before installation

Inspect the attached manifest.json and content.js without changing them. Explain exactly what browser access the extension has, what page data it reads, what it stores, and every way data can leave the page. Verify that there are no executable network calls, token/cookie access, background components, or unexpected permissions. Distinguish content-script site access from declared permissions. Flag any statement you cannot prove from the source. Do not ask me for Discord credentials, cookies, tokens, invite links, or message exports.

2. Help with setup

Using the attached README.md and manifest.json, walk me through loading this unpacked extension in [Chrome or Edge]. Keep the extension local and unpacked; do not publish it or suggest an extension store. Help me verify that the loaded card says version 0.2.0 and that I selected the folder containing manifest.json. Do not request remote browser control, credentials, tokens, cookies, or private Discord URLs.

3. Diagnose selectors safely

Diagnose why Discord Search Exporter 0.2.0 finds no results. I will provide content.js and a reviewed discord-export-debug.json in debug format 2. Do not request raw message JSON, screenshots containing messages, Discord tokens, cookies, credentials, invite links, or unredacted private URLs. Compare the debug structure with the selectors in const SEL, identify the smallest selector change, and explain why it stays confined to the search-results pane. Preserve the no-network, no-background, no-new-permissions design. Provide a patch and a focused manual test checklist.

4. Integrate the JSON locally

Design a local-only adapter from the documented Discord Search Exporter JSON schema to [describe my target tool/schema]. Use synthetic example records, not my real export. Preserve message IDs only if the target genuinely needs them, and propose an anonymization step for names, message links, channel names, emails, mentions, and invite links before analysis. Do not add uploads, telemetry, remote services, or credential handling. Give me a mapping table, validation rules, failure behavior, and tests before writing code.

5. Extend without widening trust

Propose the smallest change to Discord Search Exporter 0.2.0 to add this feature: [feature]. First inspect manifest.json, content.js, README.md, and PRIVATE-USE-NOTICE.txt. The non-negotiable constraints are: discord.com only; no fetch/XMLHttpRequest/WebSocket/sendBeacon; no account tokens or cookies; no background page/service worker; no new permissions; no telemetry; no automatic pagination; no raw content in debug output; and no weakening of the responsible-use confirmation. Explain the privacy impact, then provide a minimal patch and tests. If the feature cannot fit those constraints, say so instead of working around them.

6. Review a proposed patch

Review this patch to Discord Search Exporter as a privacy and security gate. Look specifically for new network paths, browser permissions, broader URL matches, token/cookie access, sensitive console logging, unredacted debug fields, automatic navigation, storage expansion, hidden background execution, or changes that could scrape outside the search-results pane. Check that documentation matches behavior. Rank findings by severity and cite exact files/lines. Do not approve based only on comments; verify executable code.

Source map and safe extension points

manifest.json

Browser registration and the Discord-only content-script match. Treat any new permission, URL match, or background component as a trust-boundary change requiring explicit review.

content.js → SEL

Discord DOM selectors live together near the top. Selector fixes should remain rooted in the search-results wrapper and must never fall back to the main chat scroller.

Extraction and output

extract maps rendered nodes to records; makeOutput creates the envelope. Schema adapters belong downstream when possible, after anonymization.

Diagnostics and UI

debugDump owns the minimized diagnostic. mountUI owns controls and responsible-use confirmation. Test privacy behavior whenever either changes.

Changes that require a fresh trust decision

Network access, wider site matches, automatic pagination, background execution, credentials, new permissions, remote logging, or debug content are not routine enhancements. Do not smuggle them into a selector or convenience patch.

Manual acceptance checklist

  • The extension card shows version 0.2.0 and no reported errors.
  • The panel appears on Discord and does not appear on unrelated sites.
  • The first Add page action displays the authorization reminder.
  • Adding the same page twice produces zero new records the second time.
  • Progress survives reload, while Reset clears it.
  • Save and Copy produce the documented schema with the detected query.
  • Debug format 2 contains no message text, raw IDs, or raw control labels.
  • Developer Tools shows no extension-originated network requests.

Remove and clean up

  1. Click Reset. Clear the accumulated messages and page counter.
  2. Remove the unpacked extension. Use the browser's extensions page.
  3. Delete local artifacts. Remove exports, debug reports, and extracted package copies that are no longer required.
  4. Check downstream copies. Apply the project's retention and anonymization rules to any derived files.
